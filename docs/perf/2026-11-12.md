# Final performance run: SebType next to other IMEs (#54, 2026-11-12)

SebType from main at c3e0ba7 (Android 0.1.30-sebtype.86, Windows installer 0.1.0 from CI), measured
on the same devices and with the same typing sets as the other IMEs. Every number sits next to #45's
baseline and the working budget in Decisions #2. The budgets are provisional, so nothing here passes
or fails. Medians and 95th percentiles over all keys are written "p50 / p95".

**Summary.** SebType is never far worse than the other IMEs, so no issue was filed for a number. It is
level with FUTO Keyboard on the phone, using less memory, and level with or faster than stock
fcitx5-rime and fcitx5-mozc on Linux. On Windows, its Mozc is slightly slower per key than Microsoft's
Japanese IME but converts faster. Its Weasel is faster than Microsoft Pinyin once preedit is inline.
None of the four 10+ minute mixed-typing runs crashed or grew in memory. Weasel's own Start-menu folder
is still installed (#53 D10, filed as #192).

## Devices and method

| Platform | Device | SebType | Compared with |
|---|---|---|---|
| Android | Nothing A001 (phone), Android 16 | 0.1.30-sebtype.86 | FUTO Keyboard 0.1.30 (already installed), Gboard 18.5.10 |
| Android | Emulator guide35, Android 15, x86_64 | same APK | none (see below) |
| Linux | nobara-pc, Fedora's Fcitx5 5.1.23 | its librime 1.16.1 (+ octagram), fcitx5-rime, Mozc 3.35.6354 and Chinese data | Fedora's fcitx5-rime 5.1.15 with librime 1.16.1 and rime-ice's release; Fedora's fcitx5-mozc 2.30 |
| Windows | TCSBackEnd: Windows Server 2022, 2 vCPU, 1.9 GB, zh-CN | installer 0.1.0: Weasel and Mozc | Microsoft Pinyin, Microsoft Japanese IME |

- **Android** (`android/perf/perf.sh`, new `--compare` and `--soak` modes). Every keyboard types the
  same words into the same test field with the same `monkey` taps, traced by Perfetto as #45 does.
  The other keyboards type into a private field (`kind private`), so they learn nothing on the phone.
  SebType's own numbers come from the full `perf.sh` run on the phone, because its compare run went
  wrong twice (the first typed in 日, the second's taps missed). Only that second run's open times
  were kept. Gboard's typing could not be measured: its key positions were never found (its layout
  had a number row and 拼音 on the phone, which was left as it was). Only its size, memory and
  open times are given.
- **The emulator** ran SebType's full `perf.sh` for relative numbers only. Its other keyboards are
  native x86_64 builds, while SebType's arm64 code runs translated there, so it was not compared
  with them. Linux builds and runs were running beside it.
- **Linux** (new `pc/linux/compare.sh`). Each setup gets its own Fcitx5 in a private D-Bus session
  with its own runtime dir and a throwaway profile, never the live session. SebType's libraries are
  mounted over Fedora's for that Fcitx5 alone with bwrap. `compare-keys.py` presses and releases
  keys over Fcitx5's D-Bus frontend, as an app does. It times the reply (the engine's work for the
  key) and the last candidate-panel update ("ui"). Words end with Escape, so nothing is learned.
  This replaces #45's direct librime timing, so its Rime numbers include Fcitx5 and D-Bus.
- **Windows** (`pc/windows/setup/test-tcsbackend.sh` with `ONLY=compare`). TCSBackEnd was used
  because it comes first in the user's order and worked, so Wine and YukaROG were not needed. The
  run used the test user's own RDP session with real key presses. TaikoLocalServer was idle during
  the run and was never touched. A TSF text store (`TsfHost.cs`) timestamps each key in a low-level
  keyboard hook and each edit to the field. Latency runs from the key to the first field change it
  causes, counting only keys that changed the field. Each IME was switched on through its own
  profile, then SebType was uninstalled silently and the machine checked as found. With only 2 vCPU,
  absolute numbers are slower than on a desktop. Compare the columns, not the machines.
- **Mixed typing** for leaks and crashes: 12 minutes per platform. The phone switches EN → 中 → 日
  in a loop. Linux alternates Rime and Mozc words with commits. Windows alternates Weasel and Mozc
  words. Memory was sampled every cycle or every 30 s.
- **Test data:** fixed pinyin and romaji word lists and #45's English sets. No user dictionary or
  learned words were used.

## Not compared, and why

- **Gboard's typing** on the phone: its key positions were not found (see Method).
- **Other IMEs on the emulator:** they run natively there while SebType runs translated.
- **Linux and Windows first-run times next to #45:** #45 used a different method (note ² above).

## Re-running

- Android: `android/perf/perf.sh --compare-device` and `--soak-device` (or `--compare` and `--soak`
  on the emulator), with `IME_PKG`, `IME_ID`, `KEY_ROWS` and `KEY_SPACE` for the keyboard under test.
- Linux: `pc/linux/compare.sh` (`RUNS`, `SOAK_MIN`).
- Windows: `ONLY=compare pc/windows/setup/test-tcsbackend.sh` (`SOAK_MIN`, `COMPARE_IMES`).
