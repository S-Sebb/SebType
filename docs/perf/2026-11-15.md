# Linux and Windows performance run after #190 step 4 (2026-11-15)

SebType's input method on Linux is now one Fcitx5 add-on over SebType's core (#190), in place of
SebType's own builds of Fcitx5, fcitx5-rime and fcitx5-mozc. This run measures that add-on
(`sebtype-0.1.0-3.fc44`, with librime `1.16.1-2.sebtype3.fc44`) with `pc/linux/compare.sh`, next to
Fedora's stock fcitx5-rime and fcitx5-mozc and next to [2026-11-12](2026-11-12.md), the last run before
#190. Windows was measured again on TCSBackEnd after Weasel and Mozc's Windows client were removed
([Windows](#windows-tcsbackend)). Android did not change, so it was not run again. Medians and 95th
percentiles over all keys are written "p50 / p95".

**Summary.** The add-on is level with stock per key and with 2026-11-12, and its Rime is ready much
sooner. The first measurement run found mozc_server stopped every 3 minutes. The cause was the test,
not the add-on: the server ran from where its RPM was unpacked, and Mozc's watchdog aborts a server it
does not find at the path it was built for. The tests now put the server at that path. The installed
package had the same problem, because its server was built for fcitx5-mozc's path, and this PR fixes
that too (below). With the fix, the 12-minute mixed run had no crashes. Fcitx5 used about 94 MB PSS
(100 MB RSS) in that run, against about 60 MB on 2026-11-12. The cause was the Chinese data's deploy
on the fresh profile: glibc kept the memory the deploy freed. Since release `4.fc44` SebType trims the
heap once Rime's start is done, and the same run stays at 28 MB PSS (35 MB RSS), below
([Fcitx5's memory after a deploy](#fcitx5s-memory-after-a-deploy-214)).

On Windows, SebType's own text service and server replace Weasel and Mozc's client. Its Japanese is
as fast per key as 2026-11-12's Mozc and converts faster than Microsoft's IME. Its Rime engine is at
p95 8.1 ms, inside the 10 ms budget. Windows had the same mozc_server abort every 3 minutes, from the
same watchdog check. This PR fixes that too, and the 12-minute mixed run then had no restarts.

## Device and method

nobara-pc, Fedora's Fcitx5 5.1.23, quiet apart from this run. Each setup runs in its own Fcitx5 with a
throwaway profile, in a private D-Bus session and runtime dir, never the live session. SebType's RPMs
are unpacked and mounted over Fedora's for that Fcitx5 alone with bwrap (`linux/versions.sh`,
`sebtype_run`). `compare-keys.py` presses keys over Fcitx5's D-Bus frontend and times each reply and
the last candidate-panel update ("UI"), as on 2026-11-12. SebType's Chinese and Japanese are its one
input method switched with `org.sebtype.Core1.SetLanguage`. Stock Rime gets rime-ice's release. SebType
gets its own Chinese data. Mozc starts with an empty profile in both. 5 runs over 14 pinyin words
(520 keys) and 7 romaji words (405 keys).

## Fcitx5's memory after a deploy (#214)

A fresh profile makes Rime deploy SebType's Chinese data inside Fcitx5, in Rime's own thread. The deploy
peaks at about 120 MB RSS and frees most of it when it is done, but glibc keeps the freed pages in its
heap, so Fcitx5 stayed about 30 MB higher than after a second start, for as long as it ran. Measured with
a private Fcitx5 like the soak's: start on a fresh profile, wait for 中文 and 日本語, then 60 s of mixed
typing; then the same on a second start of that profile.

| Fcitx5, RSS / PSS | Fresh profile, idle | Fresh, after 60 s typing | Second start, idle | Second, after 60 s typing |
|---|---|---|---|---|
| `3.fc44` | 55.4 / 48.6 MB | 62.5 / 55.8 MB | 31.9 / 25.2 MB | 38.5 / 32.2 MB |
| `4.fc44` (`malloc_trim` after Rime's start) | 27.6 / 21.3 MB | 34.1 / 27.8 MB | 27.4 / 21.2 MB | 34.0 / 27.8 MB |

The peak (VmHWM) was 121 MB with both. Release `4.fc44` calls `malloc_trim(0)` once, on the first key
after Rime's start or deploy is done (`core/src/rime.cpp`), which gives the freed pages back. A fresh
profile now ends where a second start does. The trim runs once per start, so it does not touch typing.

`compare.sh` again with `4.fc44` (same device, same day):

**The mozc_server restarts in the first run.** The first compare run counted 3 mozc_server restarts in
12 minutes, about 183 s apart. They come from the watchdog check described below for Linux. On Windows,
Mozc's client looks for the server where Mozc's text service is registered, or else in
`Program Files (x86)\Mozc`. SebType registers no Mozc text service and installs the server in
`Program Files\SebType`, so the watchdog's pings always failed. This was on main since #212. On
Windows, `SystemUtil::GetServerDirectory()` now returns the running program's own folder. Both
`mozc_server.exe` and `sebtype-server.exe` are installed there.

## The mozc_server restarts in the first run (Linux)

The first full run (same setup, data and device) had the same per-key numbers. Its soak counted
mozc_server going away and coming back three times, at 183 s intervals. The kernel logged an abort
each time. `private_dbus` sets RLIMIT_CORE to 1, so no core reached systemd-coredump or DrKonqi. Mozc's
`SessionWatchDog` sends Cleanup every 180 s through a Mozc client. The client accepts the server only
if `/proc/<pid>/exe` is `MOZC_SERVER_DIR/mozc_server`, the path set in `engines/mozc/src/config.bzl`.
Otherwise Cleanup and three pings fail, and the watchdog ends the server with `LOG(FATAL)`. The tests
ran the server from the unpacked RPM, so the path never matched. A 4-minute soak of the previous
package (`2.fc44`) failed the same way. That package was also built for `/usr/libexec/fcitx5-mozc` but
installs its server in `/usr/libexec/sebtype`, so an installed copy would lose its Japanese session
every 3 minutes. This PR builds Mozc for `/usr/libexec/sebtype` (release `3.fc44`). The tests overlay
the unpacked server at that path with bwrap. The second run, reported above, had no aborts.

## Re-running

`pc/linux/compare.sh` (`RUNS`, `SOAK_MIN`) and `pc/linux/perf.sh`. They build or reuse SebType's RPMs in
`~/scratch/SebType/cache/`. The stock setups need Fedora's fcitx5-rime and fcitx5-mozc and are skipped
without them (compare.sh).

Windows: `ONLY=compare pc/windows/setup/test-tcsbackend.sh` (`SOAK_MIN`, `COMPARE_IMES`) for the table
and the mixed run, and `PERF_RUN=1 pc/windows/setup/test-tcsbackend.sh` for the Rime engine rows. Both
take CI's installer for the checked-out commit.
